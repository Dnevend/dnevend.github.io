# 终端里那么多 Agent，最不值钱的就是「选哪个」

我的电脑像一座废弃的驿站。OpenCode、OpenClaw、pi 都还在；一个 cursor-agent 一年没醒过；`Applications` 里还躺着 Codex、Cursor、Trae。每个来时都自称 Agent，每个我都陪着用过几天。

后来我才明白，我一直问错了问题。不是「哪匹马好」，而是「我为什么从没学会驯马」。

> **TL;DR**
>
> - 终端窗口只是**界面**。Claude Code、OpenCode、pi 这类工具 = **外壳（Harness）+ 界面**，Agent = 模型 + 外壳。同一个模型放进不同外壳，表现可以差很远。
> - 工具之间的功能正在趋同，选型真正要看的只有三件事：**绑定什么模型、怎么收费、开放程度**。
> - 但比选型更要紧的，是**你怎么调教它**：定什么规矩、什么时候放手、什么时候签字。
> - 一句话：**一个主力 + 一个备用，剩下的功夫花在调教上，别花在装工具上。**

## 一、先拆开看：Agent 到底是什么

我们常说「打开 Claude Code」「打开 OpenCode」，好像打开的就是 Agent 本身。其实一个 Agent 可以拆成三层：

| 层 | 作用 | 例子 |
|---|---|---|
| **模型** | 大脑，负责思考和决策 | Claude、GPT、Gemini、DeepSeek、GLM、Kimi |
| **Harness（外壳）** | 跑「调模型 → 执行工具 → 把结果喂回去」的循环；管工具、权限、上下文压缩、会话 | Claude Code、OpenCode、pi |
| **界面** | 你看到的东西 | 终端 TUI、桌面 App、网页 |

理解这个分层只有一个用处：**出问题时你知道该怪谁。**

- 改错了代码、理解偏了需求，多半是**模型**的锅；
- 上下文爆了、工具调不动、权限乱拦，多半是**外壳**的锅；
- 用着别扭、看 diff 难受，那是**界面**的锅。

外壳决定了模型能用哪些工具、能看到多少上下文、能不能派子代理。所以在 Terminal-Bench 这类基准里，同一个模型换个外壳，正确率能差出二十个百分点——外壳不是可有可无的装饰，它是模型能力的另一半。

## 二、三个代表：调教权在谁手里

拿我最常用的三个对比：

| | Claude Code | OpenCode | pi |
|---|---|---|---|
| 出品 | Anthropic 官方 | 开源（anomalyco） | Mario Zechner 个人项目 |
| 模型 | 主要是 Claude | 几乎所有厂商 | 多厂商 |
| 哲学 | 功能全、开箱即用 | 厂商中立、配置项丰富 | 极简：短系统提示 + read/write/edit/bash 四个工具 |
| 调教权 | 大部分替你定了 | 明面可配，选项最多 | 全部归你，也全要你自己写 |

一句话：**Claude Code 是精装修，OpenCode 是可以换家具品牌的精装修，pi 是毛坯房加一套好工具箱。**

但别把「毛坯房」当贬义。毛坯房的意义在于**逼你自己调教**：系统提示自己写，工具自己接，压缩策略自己定。精装修和毛坯房的差别，不在功能多少，而在**调教权在谁手里**。你愿意学驯马，毛坯房就是最好的马厩；你只想骑，精装修省心。

有意思的是，pi 的内核还被嵌进了别的产品里（比如 OpenClaw）。它更像一个「Agent 引擎」，而不只是一个终端工具。

## 三、「选哪个」没有你想的那么重要

终端 CLI 有十几个：Claude Code、Codex CLI、Gemini CLI、OpenCode、Copilot CLI、Cursor CLI、Amp、Factory Droid、Goose、Aider、Qwen Code、Kimi CLI、Crush、pi……加上 IDE 内置的、云端异步的、管浏览器和消息的通用个人 Agent，名字一大串。

它们区别大吗？**比广告小，比你以为的大。** 小在功能——AGENTS.md、MCP、技能、子代理、计划模式，现在几乎是标配。大在外壳——同一个模型，换一副外壳，成绩能差二十分。

所以真正拉开差距的只有三件事：

1. **模型绑定**：官方工具往往为自家模型做过专门调优。但注意，这是因厂而异的事实，不是放之四海的规律——有官方的做得最好，也有第三方外壳跑同一个模型跑得更好。
2. **收费方式**：订阅包月，还是按 API 用量。
3. **开放程度**：能不能换模型、改提示词、写扩展。

据此，我的建议是：**一个主力 + 一个备用，就够了。** 每多装一个，就要多维护一套配置、技能和使用习惯。我电脑里那个一年没更新的 cursor-agent，就是「装了试试」的典型遗留物。

备用工具最好和主力**来自不同的模型家族**。比如主力用 OpenCode 跑 Claude，备用就选 Codex CLI。这样它可以给你「第二意见」：让不同家族的模型交叉审查同一份代码，比同一个模型自己检查自己可靠。但记住——**交叉审查是过滤器，不是验收人**。最终签字，永远是你。

## 四、该把 Agent 当主力入口吗？

我的结论是：**做工程和知识工作，值得；什么事都交给它，不值得。**

适合交给它的，是跨文件改动、排查 bug、调研、写脚本、整理资料；是那些**能沉淀的事情**——AGENTS.md、技能、MCP 一旦写好，以后每次都受益；是**有明确验收标准的任务**——测试跑通、命令输出符合预期。

不适合交给它的，恰恰是那些最「简单」的：

- **确定性的操作**：`git status`、跑一个已知命令。直接敲更快，几乎零成本。
- **一句话就能问完的问题**：聊天窗口更轻，不用背着几千 token 的工具定义。
- **审核与最终判断**：这一步必须是人，最好在 IDE 或 diff 工具里看。
- **高风险操作**：生产环境、密钥、删数据。存在提示词注入和误操作的风险，必须有权限拦截。

## 五、驯马的规矩

上面这些，都是我用几次翻车换来的。规矩本身不值钱，值钱的是**规矩是怎么来的**。下面每一条，我都把吃过的亏一并写上。

**1. 一个主管 + 一群小弟，贵的脑子只用在刀刃上。**

在 OpenCode 里，我让最强的模型只做「主管」：拆解任务、写简报、做关键决策、审结果。读代码库交给便宜快速的模型，写代码交给性价比高的模型，验收交给**另一个家族**的模型，专门找茬。

这么排，是因为写的人和审的人不能是同一个脑子——同一个模型自己检查自己，等于让嫌犯写判决书。

**2. 成本随回合数膨胀，会话要有硬预算。**

每一轮工具调用，都会把整个上下文重发一遍。最贵的不是某次输出有多长，而是回合数和上下文体积。

我踩过的坑很具体：4 个三四个小时、两百多轮的长会话，吃掉了三分之二的缓存读取费用，上下文涨到将近 50 万 token。从那以后我给自己定死：**50 轮或 150k 上下文，先到者收尾**，到了就写交接、开新会话，不硬撑；一个任务一个会话，话题岔开就新开。

**3. 「完成」不等于正确，用证据说话。**

Agent 最擅长的，是自信地说「搞定了」。没有可执行的证据（测试、命令输出），就不能算完成。每个改动收尾，要么通过，要么明确写「已改，未验证，原因是……」。我把这条写进了机器能读的规矩里，也写进了自己脑子里。

**4. 配置资产与工具解耦。**

AGENTS.md、技能、MCP 配置尽量写成通用格式，集中放在一个仓库里，再同步到各个工具。哪天从 OpenCode 换到别的工具，搬家成本很低。（顺带一句：AGENTS.md 现在几乎是各家共识，连 Claude Code 也原生读了——不过它只认 CLAUDE.md 的脾气还在，项目里一旦有个 CLAUDE.md，AGENTS.md 它就不看了。）

**5. 不要把自己养废。**

代码全交出去，你对代码库的理解会越来越浅。驯马的前提，是你自己还得是个会骑马的人。调教它，不是被它替代——是让它替你跑腿，替你记住那些吃亏换来的规矩，好让你能把脑子花在真正需要判断的地方。

## 结语

回到最初那个问错的问题。

- **都是 Agent 吗？** 都是「外壳 + 界面」。Agent 是模型和外壳的组合，看懂分层，你才知道该换的是模型还是工具。
- **哪个好？** 功能已经趋同，选它的模型、收费方式和开放程度。一个主力加一个异族备用，足够了。
- **该当主力入口吗？** 该，但要守住两条底线：**人负责验收，资产不被绑架。**

工具会一茬一茬地换，今年的第一梯队，明年未必还在。留得下来的，是你写进 AGENTS.md 的那些吃亏换来的规矩，和「没有证据就不算完成」这条底线。
